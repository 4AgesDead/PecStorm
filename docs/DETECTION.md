# Детекция грузовика на наборе «Пеленга»

## Что используется

| Параметр | Значение | Откуда |
|---|---|---|
| Модель | `yolov8x.pt` (COCO, 80 классов) | ultralytics, pretrained, без fine-tuning |
| Классы | `truck`, `car`, `bus`, `train` | на дальних планах грузовик классифицируется неустойчиво |
| `imgsz` | 960 | при 640 мелкий объект (десятки px) теряется |
| `conf` | 0.25 | ниже — растут ложные срабатывания на придорожных объектах |
| Устройство | CPU | GPU в окружении не использовался |
| Якорь | центр bbox (`cx, cy`) | см. ограничения ниже |

Реализация: `multiview3d/detect.py: YoloDetector`, обёртка источника —
`multiview3d/sources.py: DetectingFrameSource`, стадия — 
`multiview3d/truck_pipeline.py: detect_frames`, CLI — `apps/detect_truck.py`.

Фоновое вычитание как основной детектор отклонено: на статичных камерах
(cam1–cam4) оно выделяет дорогу/облака/тени, а не грузовик; объект к тому же
занимает десятки пикселей на дистанции 100–365 м.

## Проверенные факты

Быстрый прогон `apps/detect_truck.py --start 0 --end 200 --step 20`
(`yolov8x`, `imgsz=960`, `conf=0.25`):

| Камера | Кадров с детекцией | Детекций |
|---|---|---|
| cam1 | 10 из 11 | 10 |
| cam2 | 6 из 11 | 6 |
| cam3 | 0 из 11 | 0 |
| cam4 | 0 из 11 | 0 |
| cam5 | 0 из 11 | 0 |

Время: 33.4 с на 11 кадров × 5 камер ≈ **3.0 с на кадр всех камер**
(≈0.6 с на кадр одной камеры, CPU).

Причина нулей у cam3–cam5 на первых 200 кадрах: грузовик либо вне их поля
зрения, либо закрыт рельефом/деревьями. Видимость GT-пивота (верхняя оценка)
на этом интервале — `experiments/visibility_analysis.py`.

## Метрики детектора и их границы

2D-разметки (bbox) для набора нет, поэтому **precision/recall/IoU не
считаются**. Доступны:

* detection rate по камерам — прокси recall (доля кадров, где объект найден);
* средняя/медианная уверенность найденных детекций;
* время на кадр.

Команда: `python experiments/detector_benchmark.py` →
`out/experiments/detector_benchmark.json` (сравнение моделей/`imgsz`).

Чтобы получить настоящие precision/recall, нужна ручная разметка
stratified-подвыборки (§7.3 брифа): разные камеры, масштабы, окклюзии. Это не
сделано; без разметки числа precision/recall были бы выдуманными.

## Ограничения

1. **Якорь.** Центр bbox не совпадает с GT-пивотом и соответствует разным
   3D-точкам в разных видах. Детектор не даёт keypoint'ов (колёса, кабина),
   поэтому «идеального» 2D-якоря сейчас нет.
2. **Малый размер объекта.** На дистанции 100–365 м грузовик занимает
   десятки пикселей; часть кадров не детектируется (см. таблицу выше и
   `out/truck/detect_stats.json` после полного прогона).
3. **Класс.** COCO-`truck` обучен на дорожных грузовиках; конкретная модель
   (тягач с полуприцепом, светлая кабина) может классифицироваться как
   `car`/`bus`, поэтому эти классы включены.
4. **Лицензия.** `ultralytics` — AGPL-3.0; условия сдачи хакатона по
   использованию pretrained-весов организаторами не подтверждены
   (вопрос №13 в [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md)).
5. **Fine-tuning не выполнялся**: нет ручной разметки; обучать на проверочном
   наборе нельзя (утечка).
